# 15 — Dutch localisation, copy & formats

`nl-NL` is the source language. `en-GB` is a translation of it, never the reverse. If a string exists only in English, the build fails.

---

## 1. Formatting rules

| Thing | Format | Implementation |
|---|---|---|
| Currency | `€ 1.234,56` — €, non-breaking space, dot thousands, comma decimals | `Intl.NumberFormat('nl-NL',{style:'currency',currency:'EUR'})` then replace the narrow no-break space with ` ` |
| Whole euros in compact UI | `€ 1.234` | `decimals:'auto'` |
| Negative money | `−€ 42` (U+2212 minus, not hyphen) | never `(42)` |
| Percentage | `12%` (no space) | |
| Date, short | `3 sep` | `format(d,'d MMM',{locale:nl})` |
| Date, with weekday | `di 3 sep` | `format(d,'EEEEEE d MMM',{locale:nl})` |
| Date, numeric | `03-09-2026` | `dd-MM-yyyy` |
| Date, long | `3 september 2026` | |
| Month label | `september 2026` (lowercase month — Dutch does not capitalise months) | |
| Relative | `vandaag`, `gisteren`, `morgen`, `over 3 dagen`, `3 dagen geleden` | |
| Week | `week 36` | `I` |
| Time | `14:05` (24h) | |
| First day of week | **Monday** | `weekStartsOn: 1` |
| IBAN display | `NL•• •••• •••• 1234` — last 4 only | never full |
| Large counts | `1.240` (dot thousands) | |

**Test**: a snapshot test asserting `formatEUR(123456) === '€ 1.234,56'` and `formatEUR(-4200) === '−€ 42,00'`.

---

## 2. Tone rules

1. **je/jij**, never `u` outside legal texts.
2. Short sentences. Verb early. No subordinate clause stacking.
3. No exclamation marks in the product. None. (Marketing may, the app may not.)
4. No emoji in system copy.
5. No English where Dutch exists: *koppelen* not "connecten", *overzicht* not "dashboard", *potje* not "envelope", *uitgaven* not "expenses", *melding* not "notification", *bijwerken* not "syncen".
   Accepted loanwords: *app*, *account*, *budget*, *bank*, *pincode*, *e-mail*.
6. Never blame. `Je bent € 40 over je budget.` — not `Je hebt te veel uitgegeven!`
7. Never promise certainty we don't have: *waarschijnlijk*, *naar verwachting*, *schatting* where appropriate.
8. Never give advice that could be construed as financial advice. State facts and let the user act.
9. Numbers in copy always come from the formatter, never string-concatenated.

## 4. Pluralisation

Dutch has `one` / `other`. Always use i18next plural keys, never string concatenation:
```jsonc
"review_uncategorised_one":"1 transactie zonder categorie",
"review_uncategorised_other":"{{count}} transacties zonder categorie"
```
Money is never pluralised (`€ 1` not `1 euro`), except in accessibility labels where `formatMoneyForSpeech` produces `"1 euro"` / `"412 euro"`.

---

## 5. Accessibility labels

Screen readers must not read `€ 412` as "euro four hundred twelve". Provide `accessibilityLabel` via `formatMoneyForSpeech`:
```
formatMoneyForSpeech(41200)  → "412 euro"
formatMoneyForSpeech(41250)  → "412 euro en 50 cent"
formatMoneyForSpeech(-4200)  → "min 42 euro"
```
Composite example: `accessibilityLabel="Veilig te besteden: 412 euro, nog 11 dagen"`.

---

## 6. English (`en-GB`)

Same keys, British spelling, same tone rules (no exclamation marks). Dutch domain terms keep their Dutch name with a gloss on first use: *"Vaste lasten (fixed costs)"*, *"potje (savings jar)"*, *"toeslagen (benefits)"*. Do not translate `Tikkie`, `Nibud`, `iDEAL`, `Wero`, `eigen risico`, `vakantiegeld`, `jaarafrekening`.

---

## 7. Copy review checklist

- [ ] No `u` outside legal screens
- [ ] No exclamation marks
- [ ] No English loanword where a Dutch word exists
- [ ] Every number rendered by the formatter
- [ ] No blame, no praise, no gamification language
- [ ] Every claim about rights/tax/benefits hedged and linked to the authority
- [ ] Buttons are verbs
- [ ] Fits at 200% font scale
